# ЕФРСБ-агрегатор (авто/техника с фото по VIN)

Сервис-аналог [tbankrot.ru](https://tbankrot.ru):

- **парсит сообщения о продаже имущества должников** с портала ЕФРСБ
  (`bankrot.fedresurs.ru`) — раздел «автомобили и техника»;
- **парсит каталог легковых автомобилей с торгов-россии.рф**
  (раздел «купить легковой транспорт с торгов») — тип торгов, начальная/текущая
  цена, площадка, статус, дни до торгов, управляющий, порядок ознакомления;
- извлекает: **наименование имущества, описание, ФИО должника, ФИО управляющего,
  способ реализации имущества, цену, регион, VIN**;
- **ищет фото по VIN в интернете** (Яндекс.Картинки, Bing, DuckDuckGo, Avito)
  и скачивает их в своё хранилище;
- **автоматически рассылает email-запросы управляющим** по шаблону (состояние
  авто и фото) и **принимает ответы** по IMAP, парсит информацию о состоянии
  и сохраняет вложения-фото в карточку лота;
- показывает результат в веб-интерфейсе с сеткой лотов, фильтрами и фотогалереей.

## Что внутри

```
app/
├─ config.py           # настройки (env)
├─ db.py               # SQLite-хранилище (лоты, фото, прогоны, email)
├─ parser.py           # разбор текста: VIN, марка/модель, цена, регион, способ реализации
├─ emailer.py          # SMTP-рассылка запросов управляющим + IMAP-приём ответов
├─ responder.py        # разбор ответа: состояние авто + сохранение фото-вложений
├─ scraper/
│  ├─ efrsb.py         # скрейпер ЕФРСБ (live) + оффлайн-разбор HTML
│  ├─ torgi.py         # скрейпер торгов-россии.рф (RSC-payload) — легковые авто
│  ├─ session.py       # браузерная сессия, прохождение QRATOR, снапшоты
│  └─ selectors.py     # перебираемые селекторы UI
├─ photos/
│  ├─ engines.py       # поиск картинок: yandex/bing/duckduckgo/avito
│  ├─ search.py        # построение запросов по VIN и оркестрация
│  └─ download.py      # скачивание, валидация, превью (Pillow)
├─ api/                # FastAPI: /api/lots, /api/stats, /api/scrape/run ...
├─ tasks.py            # фоновые задачи
└─ static/             # фронтенд (без сборки, чистый JS)
scripts/               # serve.py, run_scraper.py, run_torgi.py, email_followup.py, export_json.py
data/                  # БД, фото, снапшоты (создаются автоматически)
```

## Быстрый старт

```bash
pip install -r requirements.txt

# подготовить браузер Playwright (однократно):
#   pip install playwright && playwright install msedge   — или chromium

# 1) запуск веб-интерфейса
python scripts/serve.py                # http://127.0.0.1:8000

# 2) CLI-скрейпинг
python scripts/run_scraper.py --days 7 --find-photos
python scripts/run_scraper.py --all-active --find-photos  # без ограничения датами
python scripts/run_scraper.py --offline data/offline   # разбор сохранённых HTML

# 3) торгов-россии.рф (легковые авто)
python scripts/run_torgi.py --pages 20                 # 20 страниц каталога с деталями
python scripts/run_torgi.py --pages 5 --no-details     # быстро, без карточек лотов
python scripts/run_torgi.py --pages 100 --send-email   # сразу после сбора отправить запросы

# 4) email по лотам
python scripts/email_followup.py                       # отправить запросы + проверить ответы
```

После запуска:
- веб-интерфейс — `http://127.0.0.1:8000/`
- API-документация — `http://127.0.0.1:8000/api/docs`
- фото — `http://127.0.0.1:8000/data/photos/...`

## Важно про банкrot.fedresurs.ru (QRATOR)

Портал защищён WAF **QRATOR** с JS-челленджем Proof-of-Work и fallback-капчей.

- При обычном обращении сайт сначала отвечает `401` и подсовывает скрипт
  `qauth_utm`, который браузер выполняет, после чего ставится cookie `qrator_jsr`
  и страница перезагружается.
- Некоторые IP QRATOR блокирует сразу — тогда даже настоящий браузер получает
  страницу `403 Error / Guru Meditation`. С такого IP (в т.ч. с текущего адреса
  этой машины, `95.79.121.34`) скрейпинг невозможен без смены сети.

Поэтому скрейпер построен на **Playwright** (настоящий браузер решает челлендж
сам), и поддерживает **прокси**:

```bash
# .env
EFRSB_HEADLESS=1
EFRSB_PROXY=http://user:pass@host:port        # или socks5://...
EFRSB_BROWSER=msedge
```

Если IP не заблокирован — первый запуск проходит челлендж, cookie сохраняются
в `data/storage_state.json` и переиспользуются на следующих запусках (быстрее и
меньше шансов на блокировку).

### Если при «Обновить данные» ошибка QRATOR

1. Запустите с `EFRSB_HEADLESS=0` — откроется окно браузера, «живой» браузер
   проходит челлендж заметно надёжнее.
2. Или укажите прокси/резидентный IP (`EFRSB_PROXY`).
3. Снапшоты проблемных моментов пишутся в `data/snapshots/`.

> Замечание: селекторы UI указаны кандидатами (`app/scraper/selectors.py`),
> верстка SPA меняется. Если очередная ревизия сайта изменит форму поиска,
> поправьте списки кандидатов. При сбое скрейпер сохраняет HTML и скриншот —
> по ним легко подобрать новые селекторы.

## Оффлайн-режим (подготовка и отладка без сайта)

Скрейпер умеет разбирать сохранённые HTML-страницы сообщений ЕФРСБ:

1. Откройте карточку сообщения на сайте и сохраните страницу (Ctrl+S) как
   `data/offline/<id сообщения>.html`.
2. Запустите `python scripts/run_scraper.py --offline data/offline`.
3. Данные попадут в базу так же, как при живом скрейпинге.

Наличие файлов в `data/offline/` не переключает веб-кнопку на оффлайн:
обычный запуск из UI всегда обращается к live ЕФРСБ.

Это удобно для сборки БД вручную и для отладки парсера.

## Поиск фото по VIN

Для каждого лота строится несколько запросов:

1. `VIN`
2. `VIN марка модель`
3. `марка модель VIN VIN`
4. заголовок лота

Перед общим поиском сервис использует указанную в сообщении ЕФРСБ электронную
площадку: извлекает её домен, ищет карточку лота по VIN/названию и сохраняет
ссылку `platform_lot_url`. С найденной карточки собираются `og:image`, изображения
галерей и ссылки на файлы изображений. Если на площадке опубликованы только PDF
или DOC-документы, они пока сохраняются как ссылки на источник, но изображения
из документов автоматически не извлекаются.

Движки (настраиваются `EFRSB_PHOTO_ENGINES`): yandex, bing, duckduckgo, avito.
Кандидаты дедуплицируются, скачиваются с правильным `Referer`, проверяются по
размеру (Pillow) и **сохраняются локально** в `data/photos/<lot_id>/`,
плюс генерируется превью. Для каждого фото хранится источник (сайт).

Запуск поиска по всем лотам без фото:

```bash
python scripts/run_scraper.py --find-photos --max-photos 200
# или кнопкой в карточке лота в веб-интерфейсе
```

## API-эндпоинты (кратко)

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/lots` | список с фильтрами: `search, category, debtor, region, sale_method, vin, has_photo, sort, page` |
| GET | `/api/lots/{id}` | детали лота + фото |
| GET | `/api/lots/{id}/photos` | фото лота |
| POST | `/api/lots/{id}/photos/search` | найти/скачать фото по VIN лота |
| GET | `/api/stats` | счётчики |
| GET | `/api/categories`, `/api/regions`, `/api/sale_methods` | варианты фильтров |
| POST | `/api/scrape/run` | запустить скрейпинг (фон) |
| GET | `/api/scrape/status` | статус последнего прогона |

## Переменные окружения

Все параметры — в [`.env.example`](.env.example): прокси, глубина поиска по
дням, кол-во страниц, движки фото, лимиты скачивания, порт.

## Юридическая заметка

ЕФРСБ — официальный реестр раскрытия сведений о банкротстве. Перед массовым
сбором данных сверьтесь с правилами пользования порталом и 152-ФЗ о персональных
данных. Фото, найденные по VIN в открытых источниках, могут относиться к тому же
автомобилю с высокой вероятностью, но не гарантируют 100% соответствия.
